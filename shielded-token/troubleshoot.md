# Shielded Token Troubleshooting Guide

## Proof Server 400/500 Errors on Mint

### Symptom
When calling `createShieldedToken` (or any shielded circuit), the proof server returns:

```
400 Bad Request: Failed Proof Server response
```

or after switching to wallet proving:

```
500 Internal Server Error: prove: expected header tag 'midnight:ir-source[v2]:', got '<!doctype html...'
```

### Root Cause

Shielded token contracts use Zswap operations (`mintShieldedToken`, `sendShielded`, `sendImmediateShielded`, `receiveShielded`). These require a **built-in ledger circuit called `output`** that proves coin commitments and nullifiers.

The `output` circuit is **NOT generated by the Compact compiler** — it is part of the Midnight ledger runtime. The compiler only generates artifacts for your contract's own circuits (`createShieldedToken`, `mintAndSend`, etc.).

When the proving provider tries to load `output.prover`, `output.verifier`, and `output.bzkir` from your contract directory, those files don't exist. Vite's dev server (in SPA mode) returns `index.html` as a fallback with HTTP 200. The proving provider then sends that HTML content to the proof server as "ZK artifact data," which the proof server rejects.

### Why Unshielded Contracts Don't Hit This

The `unshielded-token` example works because it only uses unshielded token operations (`mintUnshieldedToken`, `sendUnshielded`, `receiveUnshielded`). These don't create Zswap outputs, so the `output` circuit is never needed.

### Solutions

#### Option 1: Let the Wallet Handle Proving (Recommended for Browser Apps)

Switch from `httpClientProofProvider` (direct to local proof server) to `dappConnectorProofProvider` (delegates to the Lace wallet). The wallet has all built-in ledger artifacts bundled.

**Changes made:**
- `providers.ts`: import `dappConnectorProofProvider` and `CostModel`, make `buildProviders` async
- `api.ts`: add `await` to all `buildProviders()` calls

If the wallet still attempts to load `output` through your `FetchZkConfigProvider`, wrap the provider to reject HTML responses so the wallet falls back to its internal artifact store.

#### Option 2: Provide the `output` Artifacts to Your Local Proof Server

If you want to keep using the local proof server (`midnightnetwork/proof-server:8.0.3`), you need valid `output` artifacts in your contract directory:

```
src/contracts/keys/output.prover
src/contracts/keys/output.verifier
src/contracts/zkir/output.bzkir
```

These are ledger built-ins, not contract-specific. They can be obtained by:

1. **Extracting from the proof server Docker container** (the image may contain them):
   ```bash
   docker exec <proof-server-container> find / -name "output.prover" 2>/dev/null
   ```
   Then copy them out with `docker cp`.

2. **Mounting the proof server's artifact directory** when starting the container. Check the proof server docs for the expected mount path.

3. **Setting `MIDNIGHT_PARAM_SOURCE`** environment variable on the proof server to point to Midnight's artifact CDN so the server can fetch built-in artifacts itself.

#### Option 3: Use the Wallet's Configured Proof Server

Instead of `http://localhost:6300`, use the proof server URI from the wallet configuration:

```typescript
const config = await connectedAPI.getConfiguration();
const proofProvider = httpClientProofProvider(config.proverServerUri!, zkConfigProvider);
```

Midnight-hosted proof servers have all built-in artifacts pre-loaded.

### Validation Wrapper

If you need to prevent Vite's SPA fallback from poisoning artifact loads, wrap `FetchZkConfigProvider` to detect HTML and throw:

```typescript
class ArtifactValidatingProvider extends FetchZkConfigProvider {
  async getProverKey(circuitId: string) {
    const key = await super.getProverKey(circuitId);
    this.validate(key, `${circuitId}.prover`);
    return key;
  }
  async getVerifierKey(circuitId: string) {
    const key = await super.getVerifierKey(circuitId);
    this.validate(key, `${circuitId}.verifier`);
    return key;
  }
  async getZKIR(circuitId: string) {
    const zkir = await super.getZKIR(circuitId);
    this.validate(zkir, `${circuitId}.bzkir`);
    return zkir;
  }
  private validate(data: Uint8Array, name: string) {
    if (data.length > 0 && data.length < 5000) {
      const start = new TextDecoder().decode(data.slice(0, 50)).toLowerCase();
      if (start.includes('<!doctype') || start.includes('<html')) {
        throw new Error(`Artifact ${name} is HTML (file missing or Vite SPA fallback)`);
      }
    }
  }
}
```

This causes `getKeyMaterial()` to return `undefined` for missing artifacts, letting the proof server or wallet use its own fallback store.
